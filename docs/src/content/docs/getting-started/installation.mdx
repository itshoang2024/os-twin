## Prerequisites

| Requirement | Version | Check command |
|------------|---------|---------------|
| **PowerShell** | 7.4+ | `pwsh --version` |
| **Node.js** | 20+ | `node --version` |
| **Python** | 3.11+ | `python3 --version` |
| **Git** | 2.40+ | `git --version` |
| **pnpm** | 9+ | `pnpm --version` |

:::tip
The packaged bootstrapper and native installers can install or validate many runtime dependencies for you. Go is only required when developing or testing the packaged `ostwin-installer` binary locally.
:::

## Install OSTwin

<Tabs>
  <TabItem label="Recommended">
    Use the public bootstrapper for normal installs:

    ```bash
    curl -fsSL https://twin.igot.ai/installer.sh | bash
    curl -fsSL https://twin.igot.ai/installer.sh | bash -s -- --yes
    ```

    The bootstrapper first tries the packaged Go `ostwin-installer` release. That binary provides the guided terminal flow, downloads the matching source archive, and delegates to the native platform installer.

    If the packaged release binary is unavailable, `install.sh` falls back to the source-archive Bash installer. Checksum mismatches fail closed and do not fall back.

    Useful forwarded options:

    ```bash
    --yes
    --profile full|dashboard|minimal
    --dir ~/.ostwin
    --port 3366
    --skip-optional
    --sync-skills
    --no-start
    ```
  </TabItem>
  <TabItem label="Local Clone">
    If you already cloned the repository, run the native installer directly:

    ```bash
    git clone https://github.com/igot-ai/os-twin.git
    cd os-twin
    .agents/install.sh
    ```

    Non-interactive install:

    ```bash
    .agents/install.sh --yes
    ```

    Windows uses the PowerShell native installer:

    ```powershell
    .agents\install.ps1
    .agents\install.ps1 -Yes
    ```
  </TabItem>
  <TabItem label="Installer Dev">
    To test the packaged Go installer wrapper from a local checkout:

    ```bash
    cd installer
    go run ./cmd/ostwin-installer --source-dir .. --dry-run --yes
    go run ./cmd/ostwin-installer --source-dir ..
    go test ./...
    ```

    Release packaging is defined in `.goreleaser.yml` and automated by `.github/workflows/installer-release.yml`.
  </TabItem>
</Tabs>

## API Key Setup

OSTwin needs at least one LLM provider key. Set the key for the provider you plan to use:

<Tabs>
  <TabItem label="Anthropic (recommended)">
    ```bash
    export ANTHROPIC_API_KEY="sk-ant-..."
    ```
  </TabItem>
  <TabItem label="OpenAI">
    ```bash
    export OPENAI_API_KEY="sk-..."
    ```
  </TabItem>
  <TabItem label="Google">
    ```bash
    export GOOGLE_API_KEY="AI..."
    ```
  </TabItem>
</Tabs>

:::caution
API keys are read from environment variables at runtime. Never commit them to your plan files or role configs. The engine will fail fast if the required key is missing.
:::

For persistent configuration, add the export to your shell profile (`~/.zshrc`, `~/.bashrc`, etc.).

## Runtime File Locations

After installation, OSTwin uses the following directory structure:

| Path | Purpose |
|------|---------|
| `.agents/skills/` | Skill definitions organized by role |
| `.agents/roles/` | Role definitions (`role.json` + `ROLE.md`) |
| `.agents/war-rooms/` | Active war-room directories, created at runtime |
| `.agents/memory/` | Shared memory ledger |
| `.agents/roles/registry.json` | Role registry mapping |
| `api/` | FastAPI dashboard backend |
| `dashboard/` | Next.js dashboard frontend |
| `bot/` | TypeScript conversational bot |

## Verify Installation

Run the health check from a local checkout:

```bash
.agents/health.sh
```

On Windows:

```powershell
.agents\health.ps1
```

This checks key prerequisites and installed runtime state.

## Uninstall

To remove OSTwin:

```bash
.agents/uninstall.sh
```

On Windows:

```powershell
.agents\uninstall.ps1
```
